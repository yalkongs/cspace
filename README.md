# The Book of Color

**읽고, 조작하고, 비교하며 이해하는 색채 이론.**

## 이 책에 관하여

**The Book of Color**는 색채 이론의 주요 개념을 설명하고, 독자가 직접 조작하는 실험을 통해 그 개념을 이해하도록 만든 인터랙티브 웹북입니다. 빛의 파장에서 출발해 눈과 뇌의 지각, 빛과 물감의 혼합, 색 공간과 배색, 언어와 안료의 역사, 자연과 디스플레이의 색으로 이어집니다.

설명을 읽은 뒤 슬라이더를 움직이고, 광원을 바꾸고, 두 색을 나란히 놓아 보세요. 같은 수치가 왜 다르게 보이는지, 다른 스펙트럼이 어떻게 같은 색으로 보일 수 있는지, 화면과 물감의 혼색은 왜 다른지 살펴볼 수 있습니다. 이론과 그림을 한 화면에서 연결하는 것이 이 책의 핵심입니다.

학생과 교사, 디자이너와 개발자, 그림과 사진을 다루는 사람, 일상에서 마주치는 색이 궁금한 독자를 위해 만들었습니다. 처음부터 순서대로 읽거나, 궁금한 장의 독립 주소로 바로 들어갈 수 있습니다. 웹에서 읽는 데 계정이나 설치는 필요하지 않습니다.

## 먼저 해 볼 실험

1. **빛을 움직여 보기 — 1·2장.** 파장을 바꾸며 스펙트럼의 위치, 표시되는 색, 원추세포 반응을 비교합니다. 빛의 물리량과 지각의 관계를 생각해 볼 출발점입니다.
2. **광원을 바꿔 보기 — 2장.** 한 조명에서 비슷하던 두 표본이 다른 조명에서 어떻게 달라지는지 살펴봅니다. 메타머리즘을 옷·직물·인쇄물의 경험과 연결할 수 있습니다.
3. **빛과 물감을 섞어 보기 — 3장.** 같은 혼합 비율을 바꾸면서 서로 다른 혼색 모형의 결과를 비교합니다. RGB 값의 계산과 안료의 물리적 혼합을 구분하는 실험입니다.
4. **같은 색을 다른 배경에 놓기 — 8장.** 중심색을 고정하고 주변을 바꿉니다. 색을 독립적인 견본으로 볼 때와 화면 구성 안에서 볼 때의 차이를 관찰합니다.
5. **읽기 쉬운 배색 만들기 — 9장과 코다.** 글자·배경색과 색각 시뮬레이션을 살펴본 뒤, 팔레트를 생성하고 실제 작업에 사용할 형식으로 복사합니다.

## 관심에 따른 읽기 순서

- **처음 배우는 독자:** 1 → 2 → 3 → 4 → 5장. 빛·시각·혼색을 이해한 뒤 색상환과 색 공간으로 넘어갑니다. 낯선 용어는 10장에서 찾아볼 수 있습니다.
- **디자인·웹 개발:** 6 → 7 → 8 → 9장 → 팔레트 생성기. 조화, 지각, 맥락, 가독성을 연결합니다.
- **회화·사진·인쇄:** 2 → 3 → 7 → 12 → 14장. 조명과 혼색에서 출발해 안료와 재현 매체의 차이를 살펴봅니다.
- **역사·문화·자연:** 4 → 11 → 12 → 13장 → 연대기. 색을 분류하고 이름 붙이고 만들어 온 과정을 읽습니다.

## 실험을 읽는 방법

인터페이스에는 중성 회색 계열을 사용해 주변 UI의 색이 실험을 방해하는 일을 줄이고, 색 자체가 중심에 오도록 했습니다. 수치·곡선·설명과 색 패치를 함께 비교하며, 한 번에 하나의 변수를 바꾸어 보는 방식으로 읽으면 좋습니다.

이 책의 그림은 브라우저와 디스플레이에서 작동하는 교육용 모형입니다. 실제 단색광, 안료, 형광, 인쇄 결과를 모두 그대로 재현하지는 못합니다. 색역, 화면 설정, 주변광, 개인의 지각 차이에 따라 관찰 결과가 달라질 수 있으며, 반응시간·색각·밝기 맞추기 실험은 전문 계측이나 진단을 대신하지 않습니다. 역사적 이론과 배색 규칙 역시 각각의 맥락에서 읽어야 합니다.

키보드 조작, ARIA 설명, 상태 피드백, 동작 줄이기 설정 및 인쇄용 스타일을 고려해 구현했습니다. 개별 실험의 표현과 접근성은 지속적인 검토 대상입니다.

## 구현과 저장소 구성

최종 결과물은 **생성된 HTML과 정적 자산**입니다. Vanilla JavaScript, Canvas 2D, SVG, CSS로 실험을 구현하고 Python으로 언어별·장별 페이지를 생성합니다. 별도의 애플리케이션 서버나 프런트엔드 프레임워크 없이 GitHub Pages에서 제공합니다.

| 경로·브랜치 | 역할 |
|---|---|
| [`index32.html`](index32.html) | 현재 책의 본문·스타일·인터랙션 원본 |
| [`i18n/`](i18n/) | 언어별 번역 JSON과 용어집 |
| [`static/`](static/) | 소개·인용·404 페이지, 이미지, 보존 PDF |
| [`build/`](build/) | HTML 생성, 검증, 게시 도구 |
| `site/` | 로컬에서 생성되는 배포 결과물; `main`에는 포함하지 않음 |
| `main` | 소스, 번역, 빌드 도구와 정적 원본을 보관하는 공개 브랜치 |
| [`gh-pages`](https://github.com/yalkongs/cspace/tree/gh-pages) | 생성 결과를 그대로 게시하는 공개 배포 브랜치 |

### 로컬 빌드

Python 3.10 이상과 Node.js 20 이상이 필요합니다. 기본 빌드에 외부 패키지는 필요하지 않습니다.

```sh
git clone https://github.com/yalkongs/cspace.git
cd cspace
./deploy.sh --build-only
```

프로젝트 루트에서 번호가 가장 큰 `index<N>.html`을 원본으로 선택합니다. 현재 원본은 `index32.html`입니다. 별도 실험 폴더인 `antigravity_builds/`가 로컬에 있더라도 자동 선택하지 않습니다. 원본과 출력 위치를 직접 지정할 수도 있습니다.

```sh
python3 -B build/build.py --source index32.html --output site
```

번역 치환이 원문과 맞지 않으면 경고를 출력합니다. 빌드 성공이 번역 완성을 뜻하지는 않습니다. PDF는 `static/`에서 복사하며 HTML로부터 다시 생성하지 않습니다.

### 검증

```sh
python3 -B -m unittest discover -s build -p 'test_*.py'
node build/validate.mjs site https://yalkongs.github.io/cspace
```

빌드는 JavaScript 구문, JSON-LD, canonical URL, 언어 링크 중복, 내부 경로 및 자산을 검사합니다. 선택적인 브라우저 검사는 [`build/smoke.mjs`](build/smoke.mjs)에 있으며, Playwright와 Chrome이 별도로 필요합니다.

### GitHub Pages 배포

저장소 쓰기 권한과 GitHub CLI 인증이 있는 관리자는 다음 명령으로 배포합니다.

```sh
gh auth login
./deploy.sh
```

게시 도구는 `yalkongs/cspace`가 **공개 저장소**인지 확인한 뒤, 검증된 `site/`와 라이선스만 별도 임시 Git 작업 폴더를 통해 `gh-pages`에 올립니다. GitHub Pages는 해당 브랜치의 루트를 게시하며, `.nojekyll`로 생성 파일을 그대로 제공합니다. `/cspace/` 하위 경로와 디렉토리 인덱스를 사용하므로 Vercel의 URL 재작성 설정에 의존하지 않습니다.

기존 Vercel 배포는 과거 배포본으로 남아 있지만, 현재 `deploy.sh`는 GitHub Pages를 대상으로 합니다.
